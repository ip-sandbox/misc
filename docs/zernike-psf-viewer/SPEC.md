## 1. 背景と目的

### 1.1 背景

光学系の波面収差は Zernike 多項式の係数列で表現される。設計・評価の現場では
「この係数を少し変えたら瞳面（波面）と PSF がどう変わるか」を対話的に確かめたい場面が
頻繁にあるが、既存手段は次の理由で使いにくい。

- 商用光学設計ソフトはライセンスが必要で、手元の Windows PC で気軽に開けない。
- Python (numpy/matplotlib, poppy, prysm 等) は簡単だが、**対象環境では Python を利用できない**。
- 対象 PC には**ランタイムのインストールもできない**（Q-6 = NG）。
- Excel では 2 次元 FFT と画像表示が現実的でない。

### 1.2 目的

Zernike 係数を GUI から入力すると、**瞳面（波面）と PSF がリアルタイムに表示される**
スタンドアロンツールを、**インストール不要・ランタイム不要で Windows 上で動作する形**で提供する。

数値の規約は既存の解析パイプラインと突き合わせられるよう、
**参照実装 `torchmfbd/zern.py` に厳密に準拠**する（§5.1）。

### 1.3 想定ユースケース

| ID | ユースケース |
| --- | --- |
| UC-1 | 特定の Zernike 項（例: 球面収差 Noll 11）を単独で入れ、PSF の崩れ方を確認する |
| UC-2 | MFBD / 干渉計 / 設計ソフトが出力した係数列を読み込み、PSF と Strehl 比を確認する |
| UC-3 | 中心遮蔽など、瞳形状を変えたときの PSF 変化を比較する |
| UC-4 | スライダで係数を動かし、収差の見え方を教育・説明用にデモする |
| UC-5 | 表示中の波面 / PSF を PNG・CSV で書き出し、報告書に貼る |

### 1.4 用語

| 用語 | 意味 |
| --- | --- |
| 瞳面 (pupil plane) | 射出瞳における複素振幅分布 `P = A·exp(i·W)` |
| 波面 `W` | 参照球面からの位相。**本ツールの内部単位は rad**（§5.5） |
| PSF | 点像分布関数。瞳関数のフーリエ変換の強度 |
| λ/D | 回折限界の角度スケール。焦点面上では `λ·F#` |
| `q` | PSF のサンプリング密度 = 1 λ/D あたりの画素数。**参照実装の `overfill` と同一** |
| `N` | 瞳配列 = FFT 配列の一辺の画素数 |
| `D_pix` | 瞳直径にあたる画素数。`D_pix = (N − 1) / q`（§5.4 の注意を参照） |
| Strehl 比 | 無収差 PSF ピークに対する収差 PSF ピークの比 |
| Noll インデックス | Noll (1976) の 1 始まりの通し番号。**本ツールの正準インデックス** |

## 2. スコープ

### 2.1 本ツールが行うこと

- Zernike 係数の GUI 入力（表・スライダ・直接入力・CSV/JSON 読み書き）、**Noll 1〜231（n ≤ 20）**
- 瞳面の波面マップ（位相）・振幅マップの表示
- **単色**・非コヒーレント・遠方場（フラウンホーファー）近似での PSF 計算と表示
- 評価指標（RMS / PV / Strehl / FWHM / エンサークルドエネルギー）の算出
- MTF、スルーフォーカス（いずれもオプション機能、優先度 C）
- PNG / CSV / JSON へのエクスポート

### 2.2 本ツールが行わないこと

- 光線追跡・レンズ設計・最適化
- **多波長合成（ポリクロマティック PSF）** — Q-4 の回答により対象外（v2 以降も予定しない）
- 視野内の収差分布（フィールド依存）や像シミュレーション（畳み込み）
- 偏光・ベクトル回折・高 NA 補正
- 3D 表示（波面の立体レンダリング）※ v2 以降の候補
- **多言語 UI** — Q-8 の回答により日本語のみ

### 3.2 採用構成 (H-1) の要件

| ID | 要件 |
| --- | --- |
| C-1 | Windows 10 (21H2 以降) / Windows 11 の**既定ブラウザ（Edge / Chrome）で動作**すること |
| C-2 | Python ランタイムに依存しないこと |
| C-3 | **インストール・管理者権限・ランタイム導入のいずれも不要**であること |
| C-4 | 2D FFT (`N` = 512〜1024) をインタラクティブ速度で回せること |
| C-5 | 2 次元画像をカラーマップ付きで高速描画できること |
| C-6 | 配布物は **`.html` 1 ファイル**であること。外部ファイル参照を持たないこと |

成果物は `ZernikePsfViewer.html` 1 個。HTML / CSS / JS / カラーマップ / （WASM を使う場合は
base64 埋め込みの wasm バイナリ）をすべてインライン化する。ビルドは `esbuild` によるバンドルと
インライン化のみで、**配布先には Node もブラウザ以外の何も不要**。

### 3.3 `file://` の制約と回避策（設計時に必ず織り込むこと）

| 制約 | 回避策 |
| --- | --- |
| ES モジュール (`<script type="module">` / `import`) は CORS で読めない | 全部インラインの **classic script** として束ねる |
| `fetch()` でローカルファイルを読めない | WASM は base64 で埋め込み `WebAssembly.instantiate(bytes)` で起動。データも埋め込み |
| Web Worker を外部 `.js` から生成できない | `new Worker(URL.createObjectURL(new Blob([src])))` で生成する。**Chromium では `file://` からでも起動することを実機で確認済み**。ただし生成できても起動しない環境がありうるうえ、その場合 `onerror` が飛ばず沈黙するため、**起動直後に ping/pong のハンドシェイク（既定 800 ms）を行い、応答が無ければメインスレッド実行に切り替える**。URL に `?backend=main` / `?backend=worker` を付けて経路を固定することもできる |
| `localStorage` が opaque origin で使えないことがある | 必ず try-catch し、失敗時は「設定 JSON のダウンロード / 読込」に一本化する |
| ファイル入出力 | 読込は `<input type="file">`、書出しは `<a download>`。いずれも `file://` の Edge / Chrome で動作する |
| WebGL2 が使えない環境がありうる | 起動時に `getContext("webgl2")` を試し、失敗したら Canvas2D 経路へ自動フォールバック |

### 3.5 計算バックエンドの方針（実測値）

`N = 1024` の 2D 複素 FFT の演算量はおよそ `2·N²·log₂N ≈ 1×10⁸ flops`。

**実測**（Node 22 / V8。Chromium と同じエンジンなのでブラウザの目安になる。`tools/bench.js`）:

| 処理 | `N=512` | `N=1024` | `N=2048` |
| --- | ---: | ---: | ---: |
| 2D FFT（列パス素朴） | 36.3 ms | 166.3 ms | 746.2 ms |
| 2D FFT（列パスをブロック転置） | 14.3 ms | 66.7 ms | — |
| フルパイプライン `compute`（3 モード） | **13.1 ms** | **51.7 ms** | 338.7 ms |
| 同・231 モードすべて非ゼロ | — | **72.5 ms** | — |
| 基底マップ 1 モード生成（n=20） | 1.0 ms | 3.6 ms | — |

**結論: 素の JavaScript で §8.2 の目標を満たすため、WASM 化は不要。**

実装で効いた最適化（順に効果が大きい）:

1. **列パスのブロック転置** — 列方向 FFT は stride `N` のアクセスになりキャッシュミスで
   極端に遅くなる。32×32 のブロック転置を挟んで行パスに変換すると、`N=1024` の列パスが
   **134 ms → 29 ms**、2D FFT 全体で **3 倍**速くなる（転置 2 回分を含めても得）。
2. **基底マップのキャッシュ** — 係数変更時の再計算は線形結合と FFT だけ（§4.2、§4.3）。
3. **ゼロ行スキップ** — 瞳は `N` 行のうち `D_pix` 行しか非ゼロでない（既定 256/1024）。
   行パスをその範囲に限ると `N=1024` で **33%** の削減（`N=512` で 27%）。
   > v0.3 では演算量から「約 38%」と見積もっていたが、転置導入前の実測は 18% だった。
   > 列パスが支配的だったためで、転置で列パスを速くした結果 33% まで戻った。
4. **二段品質** — ドラッグ中は `N=512`、離した時点で `N=1024`（§8.2）。
5. **Web Worker への隔離** — 計算中も UI が固まらない。最新入力以外は破棄する。
   Worker が使えない環境ではメインスレッドで実行する（§3.3）。この場合 `N=1024` の
   計算中に約 52 ms のブロッキングが発生するが、ドラッグ中は `N=512`（13 ms）なので実用上問題ない。

### 3.6 描画方式

**WebGL2 を主経路とする。** `R32F` テクスチャに強度・波面を 1 回だけアップロードし、
対数 / γ / 表示レンジ / カラーマップ / ズーム・パンを**フラグメントシェーダで適用**する。

これにより **「PSF の対数下限スライダを動かす」「カラーマップを変える」「ズームする」が
すべてユニフォーム変更だけで済み、FFT の再実行もテクスチャの再アップロードも不要**になる。

WebGL2 が使えない場合は Canvas2D + `putImageData`（JS 側でカラーマップ適用）に自動で落とす。
この場合、表示パラメータの変更ごとに `N²` 画素のカラーマップ再適用が発生する（10〜30 ms）。

### 3.7 決定が覆る条件

| 条件 | 切替先 |
| --- | --- |
| 実測で JS の性能が §8.2 に届かない | 計算カーネルのみ WASM 化（UI 無変更） |
| WASM でも届かない | H-3（Tauri + Rust）。UI 資産はそのまま流用できる |
| 計算機と閲覧端末を分けたい / CLI と同居させたい | H-2（付録 E に要件メモを残してある） |
| ブラウザの使用自体が禁止された | E（PowerShell 単一 `.ps1`） |

## 4. アーキテクチャ

### 4.1 モジュール構成

```
zernike-psf/
├─ src/core/                  … UI 非依存。DOM を一切参照しないこと
│   ├─ nollIndex.ts           … Noll j ⇔ (n,m) 変換（§5.3）。OSA/Fringe 変換もここ
│   ├─ zernikePolynomial.ts   … R_n^m（BigInt で厳密係数）と正規化、基底マップ生成
│   ├─ basisCache.ts          … 基底マップの遅延生成・パック格納・LRU（§4.3）
│   ├─ pupil.ts               … 瞳マスク（円形・中心遮蔽・スパイダー・矩形・任意画像）
│   ├─ fft.ts                 … 1D/2D 複素 FFT（radix-2, in-place, ゼロ行スキップ）
│   ├─ mft.ts                 … Matrix Fourier Transform（§5.7.1、ズーム表示用）
│   ├─ psf.ts                 … 瞳関数 → PSF / OTF / MTF
│   └─ metrics.ts             … RMS, PV, Strehl, FWHM, EE
├─ src/worker/
│   └─ computeWorker.ts       … core を呼ぶ Web Worker。Transferable で結果を返す
├─ src/render/
│   ├─ glImage.ts             … WebGL2: R32F テクスチャ + カラーマップ/対数/γ シェーダ
│   ├─ canvasImage.ts         … Canvas2D フォールバック
│   ├─ colormaps.ts           … viridis / inferno / coolwarm / grayscale の LUT
│   └─ plot.ts                … 断面・MTF の 1D プロット（Canvas2D）
├─ src/ui/                    … 係数表・スライダ・パネル・入出力（日本語のみ）
├─ src/io/                    … JSON / CSV / PNG の読み書き（§7）
├─ tests/
│   ├─ *.test.ts              … Vitest
│   └─ fixtures/              … 参照実装から生成した数値（§10.3、付録 C）
└─ build/
    └─ inline.mjs             … esbuild で単一 HTML にインライン化（成果物）
```

**計算の実行場所の差し替え点は `src/worker/` の 1 か所に閉じ込める。**
「入力 = 設定オブジェクト、出力 = `Float32Array` の波面・PSF」という同一インタフェースを
保つ限り、JS → WASM → ネイティブ (H-3) の移行で UI コードを変更せずに済む。

### 4.2 計算パイプライン

```
 [Zernike 係数 a_j (Noll, rad)]     [光学設定 N, q, 瞳マスク]
        │                                  │
        ▼                                  ▼
  基底マップキャッシュ  ────────►  波面 W = Σ a_j Z_j   [rad]
   （項ごとに 1 回だけ生成）                │
                                           ▼
                            瞳関数 P = A · exp(i·W)      ← 瞳マスク A
                                           │
                                           ▼
                                    2D FFT + fftshift
                                           │
                     ┌─────────────────────┼──────────────────┐
                     ▼                     ▼                  ▼
              PSF = |F|² / Σ         指標 (Strehl 等)      OTF / MTF
                     │
                     ▼
      WebGL2 テクスチャ（Float32）→ シェーダで対数/γ/レンジ/カラーマップ
```

### 4.3 メモリとキャッシュ戦略（n ≤ 20 対応）

Q-5 により最大 **231 モード**を扱う。基底マップを素直に全保持するとメモリが問題になるため、
以下を必須とする。

| ID | 要件 | 根拠・見積り |
| --- | --- | --- |
| AR-1 | 基底マップは **マスク内画素のみを 1 次元 `Float32Array` にパックして保持**する | `N=1024`, `D_pix=256` で 1 モードあたり 51,472 要素 ≈ 206 KB。2 次元で持つと 4 MB になる |
| AR-2 | 基底マップは**遅延生成**する（係数が非ゼロになった項だけ作る） | 実利用では非ゼロ項は数個〜十数個。231 個すべてを作る必要はない |
| AR-3 | キャッシュは **LRU** とし、**上限を既定 128 MB**（設定可能）とする | 全 231 モード保持で約 47.6 MB（`N=1024, D_pix=256`）。`D_pix` を上げると 2 乗で増えるため上限は必須 |
| AR-4 | 波面の合成は**非ゼロ係数の項のみ**を走査する | 231 項全走査でも `231 × 51,472 ≈ 1.2×10⁷` MAC（約 20 ms）だが、通常は 1 桁以上小さい |
| AR-5 | `N` または瞳マスクが変わったらキャッシュを全破棄する | 基底マップはグリッドに依存する |

## 5. 計算仕様

### 5.1 準拠する参照実装（Q-1 の回答）

本ツールの Zernike 規約は次の実装に**厳密に準拠**する。

- リポジトリ: `aasensio/torchmfbd`
- ファイル: `src/torchmfbd/zern.py`（`zernIndex`, `ZernikeNaive.R_nm`, `ZernikeNaive.Z_nm`）
- 使用箇所: `src/torchmfbd/deconvolution.py` の `precalculate_zernike` / `compute_psfs`

参照実装から確定する規約は次の 6 点である（詳細は付録 C）。

| # | 規約 | 内容 |
| --- | --- | --- |
| R-1 | インデックス | **Noll**（1 始まり）。`zernIndex(j)` で `(n, m)` に変換（§5.3） |
| R-2 | 正規化 | **Noll 正規化（RMS 正規化）を常に適用**。`m=0` は `√(n+1)`、`m≠0` は `√(2(n+1))`。ただし `n=m=0`（ピストン）は `1` |
| R-3 | 方位角 | `m > 0 → cos(\|m\|θ)`、`m < 0 → sin(\|m\|θ)`、`θ = atan2(y, x)` |
| R-4 | グリッド | `x = linspace(−1, 1, N)`（両端を含む）、`ρ = q·√(x²+y²)`、瞳マスクは `ρ ≤ 1` |
| R-5 | 位相の単位 | **ラジアン**。`P = mask · exp(i·W)`（`W` に `2π` は掛けない） |
| R-6 | PSF | `psf = \|FFT2(P)\|²` を**総和で正規化**。`otf = FFT2(psf_norm)` |

> **相互運用上の重要な注意:** 参照実装の呼び出し側は `noll_Z = 2 + arange(n_modes)` としており、
> **モード列の先頭は Noll j = 2（X チルト）** である（ピストンを含まない）。
> 本ツールは Noll j = 1 から扱うため、外部データを読み込む際は
> **先頭要素が j=1 か j=2 かを指定できること**（§7.2 の `nollStart`）。

### 5.2 Zernike 多項式の定義

単位円 `0 ≤ ρ ≤ 1`, `0 ≤ θ < 2π` 上で定義する。

動径多項式:

```
                (n-|m|)/2       (-1)^s (n-s)!
R_n^|m|(ρ) =      Σ      ──────────────────────────────── ρ^(n-2s)
                 s=0     s! ((n+|m|)/2 - s)! ((n-|m|)/2 - s)!
```

`n − |m|` が奇数のとき `R_n^|m| ≡ 0`。

多項式本体（R-2, R-3 に従う）:

```
n = 0, m = 0 :  Z = 1
m = 0, n > 0 :  Z = √(n+1)     · R_n^0(ρ)
m > 0        :  Z = √(2(n+1))  · R_n^m(ρ)   · cos(m·θ)
m < 0        :  Z = √(2(n+1))  · R_n^|m|(ρ) · sin(|m|·θ)
```

この正規化のもとで、単位円上（遮蔽なし）で `(1/π)∫∫ Z_i Z_j ρ dρ dθ = δ_ij` が成り立ち、
係数 `a_j` はその項の RMS 波面誤差（rad）そのものになる。

### 5.3 インデックス変換

**Noll j → (n, m)**（参照実装 `zernIndex` と同一のロジック）:

```
n = floor( (−1 + √(8(j−1)+1)) / 2 )
p = j − n(n+1)/2
k = n mod 2
m = floor((p + k)/2) · 2 − k
if m ≠ 0:
    m = +m  (j が偶数)
    m = −m  (j が奇数)
```

逆変換 `(n, m) → j` は上式を満たす `j` を `n(n+1)/2 + 1 … (n+1)(n+2)/2` の範囲で探索するか、
起動時に `j → (n,m)` の対応表を 1 回だけ構築して逆引きする（**231 件しかないため後者で十分**）。

OSA/ANSI (`j = (n(n+2)+m)/2`) と Fringe
(`j = (1 + (n+|m|)/2)² − 2|m| + floor((1 − sgn m)/2)`) の変換も提供するが、
**正準インデックスは Noll であり、UI の既定表示も Noll とする**（付録 A）。

### 5.4 座標系とグリッド

```
x[i] = −1 + 2i/(N−1)            i = 0 … N−1     （両端を含む）
xx[row][col] = x[col]           … 列方向が x
yy[row][col] = x[row]           … 行方向が y
ρ[row][col]  = q · √(xx² + yy²)
θ[row][col]  = atan2(yy, xx)
瞳マスク A   = 1  (ρ ≤ 1),  0  (ρ > 1)
```

- 配列インデックスは `[行 = y][列 = x]`。**行 0（y = −1）を画面の上に描画する**
  （`imshow(origin='upper')` と同じ）。したがって画面上では **y は下向きが正**である。
- `q` は参照実装の `overfill` と同一で、**1 λ/D あたりの像面画素数**である。
  参照実装では `q = 206265 · λ / (D · pixel_size[arcsec])` として物理量から求めている。

> **`D_pix` の定義に関する注意:** `linspace(−1, 1, N)` は間隔が `2/(N−1)` の
> **端点を含むグリッド**であり、画素中心グリッド（間隔 `2/N`）ではない。
> したがって瞳直径は厳密には **`D_pix = (N − 1)/q` 画素**である。
> 画素中心グリッドを使うと参照実装と一致しないため、**必ず端点を含むグリッドを用いること**。

| 条件 | 値 |
| --- | --- |
| ナイキスト条件 | `q ≥ 2`。下回る設定は UI で警告 |
| 推奨値 | `q = 4` |
| 既定 | `N = 1024`, `q = 4` → `D_pix ≈ 255.8` |
| プレビュー | `N = 512`, `q` は同じ → `D_pix ≈ 127.8`（瞳サンプリングが粗くなる点は許容する） |

UI では **`N`（配列サイズ、2 のべき乗）と `q`（サンプリング）を入力**させ、
`D_pix = (N−1)/q` を計算結果として表示する。

### 5.5 波面と単位

```
W(row, col) = Σ_j a_j · Z_j(ρ, θ)        [rad]
```

**内部単位は rad**（R-5）。UI では入力単位を切り替えられる。

| 単位 | 内部値への換算 | 用途 |
| --- | --- | --- |
| **rad**（既定） | `a[rad] = 入力値` | 参照実装・MFBD 出力との突き合わせ |
| λ（波数） | `a[rad] = 2π · 入力値` | 光学の慣用表記 |
| nm | `a[rad] = 2π · 入力値 / λ[nm]` | 干渉計出力など |

波長 `λ [nm]` は nm 単位を使う場合にのみ必要（既定 550 nm）。

ピストン（Noll 1）とチルト（Noll 2, 3）は PSF の形状を変えず位置だけを動かすため、
**「ピストン/チルトを除外して指標を計算する」チェックボックス**を設ける（既定 ON）。

### 5.6 瞳関数

```
P = A · exp(i · W)
```

`A` は瞳の振幅透過率で、次を合成して構成する。

| 要素 | パラメータ |
| --- | --- |
| 円形開口 | `ρ ≤ 1`（基本形。参照実装と同一） |
| 中心遮蔽 | 遮蔽比 `ε = 0.0〜0.9`（`ρ < ε` を 0 にする） |
| スパイダー | 本数 (0/3/4)、幅 [画素]、回転角 |
| 矩形／正方 | 幅・高さ [画素] |
| ガウシアンアポダイゼーション | `A = exp(−(ρ/w)²)`、`w` 可変 |
| 任意マスク | 8bit グレースケール PNG を読み込み `A = pixel/255` |

> **注意（実装者向け）**: 中心遮蔽や非円形瞳では Zernike の直交性が崩れる。
> **RMS を係数の二乗和 `√(Σ a_j²)` から求めてはならず、マスク内の波面マップから
> 数値的に計算する**こと。UI 上でもこの旨を注記する。

### 5.7 PSF

```
PSF = | FFT2(P) |²        （fftshift して中心を原点に）
```

正規化は次の 2 方式を切り替え可能とする。

1. **総和正規化**: `Σ PSF = 1` — **参照実装と同一。既定**
2. **無収差ピーク正規化**: 同一瞳マスクの無収差 PSF のピークを 1 とする
   （表示ピーク値がそのまま Strehl 比になる）

像面の画素スケール:

```
Δθ  = (1/q) · (λ/D)   [rad]
Δx' = (1/q) · λ · F#   [長さ]
```

#### 5.7.1 ズーム表示のための MFT（優先度 S）

FFT でズームすると「倍率を上げる = `q` を上げる = `N` を増やす」となり、
`±4 λ/D` を細かく見たいだけでも巨大な配列が要る（`q=16` なら `N=4096`）。

これを避けるため **MFT (Matrix Fourier Transform, Soummer et al. 2007)** を併用する。

```
E_img = F_y · P · F_xᵀ
  F_x[k, l] = exp( −i·2π · u_k · x_l )      (N_img × N_p)
```

| | FFT | MFT |
| --- | --- | --- |
| 計算量 | `O(N² log N)` | `O(N_p²·N_img + N_p·N_img²)` |
| `q` | `N/D_pix` の離散値のみ | **任意の実数値**を直接指定できる |
| 出力範囲 | 常に全視野 | **必要な範囲だけ**計算できる |
| 向き | MTF、全視野、エネルギー総和 | **ズーム表示、コア付近の詳細** |

実装方針: 既定表示と MTF・エネルギー総和は FFT 経路、ズームイン時は MFT 経路。
両経路の一致を UT-15 で検証する。v1 では FFT 経路のみでも要件は満たせる。

### 5.8 評価指標

| 指標 | 定義 | 備考 |
| --- | --- | --- |
| PV | `max(W) − min(W)`（マスク内） | 表示単位は UI 設定に従う |
| RMS `σ` | `√( Σ A²(W−W̄)² / Σ A² )` | マスク内。振幅重み付き |
| Strehl（定義値） | `S = abs( Σ A·e^{iW} )² / (Σ A)²` | 原点における強度比。厳密 |
| Strehl（実測ピーク比） | `max(PSF_ab) / max(PSF_ideal)` | 両方表示する |
| Maréchal 近似 | `S ≈ exp(−σ²)` | **`σ` は rad 単位 RMS**（λ 単位なら `exp(−(2πσ)²)`）。`σ ≲ 0.6 rad` で有効 |
| FWHM | PSF の半値全幅 | `λ/D` 単位。放射平均から補間で算出 |
| EE(r) | 半径 `r` 内の全エネルギー比 | 半径は `λ/D` 単位 |

### 5.9 OTF / MTF（優先度 C）

```
OTF(f) = FFT2( PSF_norm )            ← 参照実装と同一（総和正規化済みの PSF を変換）
MTF(f) = |OTF(f)|
```

周波数軸は `Δf = q / (N · λ · F#)`。理想瞳のカットオフ `f_c = 1/(λ·F#)` は
配列上でちょうど `D_pix` 画素目にあたる（実装の検算に使える）。

### 5.10 数値仕様

| 項目 | 仕様 |
| --- | --- |
| 実数型 | 計算は `Float64Array`、GPU 転送と保存は `Float32Array` |
| FFT | radix-2 Cooley–Tukey、in-place、twiddle 係数を事前計算してキャッシュ、ゼロ行スキップ |
| FFT サイズ `N` | 256 / 512 / 1024 / 2048（2 のべき乗のみ） |
| 最大次数 | **`n ≤ 20`（Noll j = 1〜231）** |
| **動径多項式の係数** | **`BigInt` で厳密に整数計算してから `Number()` に変換する**（下記参照） |
| 多項式の評価 | 係数を `ρ²` の多項式として Horner 法で評価（`ρ^(n−2s)` を都度べき乗しない） |
| 角度計算 | `Math.atan2(y, x)`。`ρ = 0` の点では `θ = 0` |

> **`BigInt` を必須とする理由:** `n = 20` では `R_n^m` の定義式に `20! = 2.43×10¹⁸` が現れ、
> IEEE754 倍精度の整数厳密範囲 `2⁵³ ≈ 9.01×10¹⁵` を超える。
> 倍精度のまま階乗を計算しても最終的な比は相対誤差 `~10⁻¹⁵` に収まるが、
> **次数上限を将来引き上げたときに静かに壊れる**ため、係数は `BigInt` で厳密に求め、
> 約分後に `Number()` へ落とす。係数はモードごとに 1 回だけ計算すればよく、性能上の問題はない。

## 7. データ仕様

### 7.1 設定ファイル（JSON）

拡張子 `.zpsf.json`。UTF-8 (BOM なし)。

```json
{
  "schemaVersion": 1,
  "coefficientUnit": "rad",
  "wavelengthNm": 550.0,
  "indexScheme": "Noll",
  "coefficients": [
    { "n": 2, "m": 0,  "value": 0.30 },
    { "n": 4, "m": 0,  "value": 0.60 },
    { "n": 3, "m": 1,  "value": -0.12 }
  ],
  "pupil": {
    "shape": "circular",
    "obscurationRatio": 0.0,
    "spider": { "count": 0, "widthPixels": 2.0, "rotationDeg": 0.0 },
    "apodization": { "type": "none", "width": 1.0 }
  },
  "grid": {
    "fftSize": 1024,
    "samplingQ": 4.0,
    "previewFftSize": 512
  },
  "psf": { "normalization": "sum" },
  "display": {
    "psfScale": "log",
    "psfLogFloorDb": -50.0,
    "psfZoomLambdaOverD": 16.0,
    "wavefrontColormap": "coolwarm",
    "psfColormap": "viridis",
    "excludePistonTilt": true
  }
}
```

- **係数は必ず `(n, m)` で保存する。** インデックス番号で保存すると方式変更で破綻する。
- `schemaVersion` が未知の場合は読み込みを中止し、理由をダイアログで表示する。
- 未知キーは無視する（前方互換）。欠落キーは既定値で補う。

### 7.2 係数 CSV

読み込み時は次の 2 形式を自動判別する。ヘッダ行（`#` 始まりまたは非数値行）は無視。

```
# 形式 1: インデックス, 値
4,0.30
11,0.60

# 形式 2: n, m, 値（方式に依存しないため推奨）
2,0,0.30
4,0,0.60
```

**形式 1 を読む際は次の 2 つを UI で指定できること（既定値は括弧内）。**

| 設定 | 説明 | 既定 |
| --- | --- | --- |
| インデックス方式 | Noll / OSA / Fringe | Noll |
| `nollStart` | 先頭要素に対応する Noll 番号。**参照実装 (torchmfbd) のモード列は `2` から始まる**（§5.1） | 1 |
| 単位 | rad / λ / nm | rad |

値だけが 1 列に並んだファイル（インデックス列なし）も、`nollStart` から連番として解釈する。
区切りはカンマ / タブ / 空白を許容。小数点はピリオドのみ。書き出しは常に形式 2。

### 7.3 マップ CSV

`N` 行 × `N` 列の数値。1 行目に `# key=value` 形式のメタ情報を出力する。

```
# type=wavefront unit=rad N=1024 q=4.0 D_pix=255.75
# type=psf unit=normalized_sum N=1024 q=4.0 lambdaOverD_perPixel=0.25
```

### 9.2 係数表（231 モード対応）

Q-5 により最大 231 行になるため、次を必須とする。

| 要件 | 内容 |
| --- | --- |
| グループ化 | radial order `n` ごとの折りたたみセクション。ヘッダに項数と「そのグループの非ゼロ数」を表示 |
| 既定の展開状態 | `n ≤ 4`（Noll 1〜15）を展開、`n ≥ 5` は折りたたみ |
| 仮想スクロール | 展開時も DOM 行数を可視範囲＋数行に抑える |
| 絞り込み | 「非ゼロのみ」トグル、Noll 番号・`(n,m)`・名称のインクリメンタル検索、`n_max` セレクタ |
| 行の内容 | Noll j / (n,m) / 名称 / 数値入力 / スライダ。**名称のツールチップに `(n,m)` と他方式の番号を表示** |
| 非ゼロ行の強調 | 背景色を変え、折りたたまれていても「n=7 に 2 項」等がヘッダで分かるようにする |

> 名称（「X コマ」「0/90° 非点」等）は文献によって X/Y や 0/90 の割り当てが逆になることがある。
> **本ツールは `(n, m)` を正とし、名称は表示用ラベルにすぎない**旨をツールチップに明記する。

### 9.3 表示仕様

| 対象 | 既定カラーマップ | スケール |
| --- | --- | --- |
| 波面（位相） | 発散型 coolwarm（0 = 白）。**0 を中心に対称なレンジ** | リニア。レンジは自動 or 手動 |
| 瞳振幅 | グレースケール | 0〜1 固定 |
| PSF | viridis（他に grayscale, inferno, hot） | 対数（既定, 下限 −50 dB）/ リニア / γ (0.1〜1.0) |
| MTF | viridis | リニア 0〜1 |

- マスク外領域は中間グレー（`#404040`）で塗り、データ無しを明示する。
- カラーバーは画像の右に常時表示し、最小・最大値を数値で添える。
- マウスカーソル位置の座標と値をステータスバーに表示する
  （瞳面: `(x, y), W [rad]` / PSF: `(λ/D 単位座標), 正規化強度`）。
- **行 0（y = −1）を画面の上に描画する**（§5.4）。画面上で y は下向きが正。

## 10. テスト計画

### 10.1 単体テスト（`node --test`、外部依存なし）

| ID | 対象 | 期待値 |
| --- | --- | --- |
| UT-01 | `R_n^m` の値 | `R_4^0(0)=1`, `R_4^0(1)=1`, `R_4^0(0.5)=−0.125`, `R_2^0(ρ)=2ρ²−1` を全域で一致（誤差 < 1e-12） |
| UT-02 | 正規化 Zernike の直交性 | `D_pix = 512` で `n ≤ 6` の全ペアが `(1/π)∫Z_iZ_j ≈ δ_ij`（誤差 < 5e-3、実測 2.6e-3）。`n = 20` の対角成分は誤差 < 1e-2（実測 6.4e-3）。**誤差は円形マスクの画素量子化に由来し `O(1/D_pix)` で減衰する**（N を倍にすると半減することを確認済み） |
| UT-03 | Noll ⇔ `(n,m)` の全単射 | `j = 1…231` を往復変換して同一値に戻ること |
| UT-04 | **Noll 変換の参照実装一致** | `j = 1…231` の `(n,m)` が参照実装 `zernIndex(j)` の出力と**全件一致**（付録 C の fixture と突き合わせ） |
| UT-05 | **`BigInt` 係数の厳密性** | `n = 20` の全 `m` について、`BigInt` 由来の係数が既知の整数列と完全一致すること。倍精度階乗版との相対差が 1e-12 未満であることも記録する |
| UT-06 | FFT | ランダム配列で naive DFT と一致（`N=64`、誤差 < 1e-10）。逆変換の往復同一性 |
| UT-07 | パーセバル則 | `Σ abs(P)² = (1/N²)·Σ abs(FFT(P))²`（誤差 < 1e-10） |
| UT-08 | ゼロ行スキップ最適化 | 最適化あり／なしの FFT 結果が相対誤差 < 1e-12 で一致 |
| UT-09 | 無収差 PSF | 円形瞳・全係数 0 のとき、第 1 暗環半径が `1.22 λ/D` と 1% 以内で一致、Strehl = 1.000 |
| UT-10 | Airy 一致 | 無収差 PSF の放射断面が `[2J₁(v)/v]²` と相対誤差 2% 以内（ピーク近傍 5 λ/D まで） |
| UT-11 | チルトの効果 | Noll 2 に係数 `a` [rad] を与えると PSF が **`2a/π · λ/D`** だけ移動する（誤差 0.1 画素以内、`q=8`） |
| UT-12 | Maréchal 近似 | 純デフォーカス `σ = 0.1〜0.5 rad` で厳密 Strehl と `exp(−σ²)` が 2% 以内で一致 |
| UT-13 | 遮蔽瞳 | `ε = 0.5` で無収差 PSF のピークが下がり第 1 暗環が内側に寄る。総エネルギー保存を確認 |
| UT-14 | MTF | 無収差・円形瞳の MTF がカットオフ `f_c` で 0 に達し、`(2/π)(arccos ν − ν√(1−ν²))` と 1% 以内で一致 |
| UT-15 | MFT と FFT の一致 | 同一 `q`・同一範囲で両経路の PSF が相対誤差 < 1e-6 で一致（§5.7.1） |
| UT-16 | JSON 往復 | 保存 → 読込で全パラメータが一致 |
| UT-17 | CSV 解析 | 形式 1/2、`nollStart` = 1/2、単位 rad/λ/nm、区切り違い、BOM 付き、CRLF/LF、空行・コメント行の混在 |
| UT-18 | **参照実装との数値一致** | 付録 C の fixture と一致すること。零点近傍では相対誤差が発散するため **2 つの尺度**で判定する: `normAbs`（最大絶対誤差をマップのピーク値で正規化）と `relSig`（ピークの 1e-6 を超える画素のみの相対誤差）。倍精度経路で `normAbs < 1e-12` / `relSig < 1e-11`（実測 1.4e-14 / 7.4e-13）、実行時の Float32 基底経路と合成波面・PSF で `normAbs < 1e-6` / `relSig < 1e-5`（実測 4.9e-8 / 1.6e-6） |
| UT-19 | 基底キャッシュ | LRU 上限を超えて使ってもメモリ上限を守り、キャッシュヒット時とミス時で結果が同一であること。グリッド変更で全破棄されること |
| UT-20 | **Worker のグルーコード** | `src/worker/workerGlue.js` を Node の `vm` で疑似 Worker として動かし、(a) `ping` に `pong` を返す、(b) `compute` の結果がメインスレッドの `Engine` とビット単位で一致する、(c) 転送リストに重複が無く payload の全配列を覆う、(d) `idealProfile` はコピーを渡す（キャッシュを detach しない）、(e) 異常入力で `error` を返して沈黙しない、ことを検証する |
| UT-21 | 入力検証 | `N` が 8〜8192 の整数でない、`q` が非正、FFT 経路で `N` が 2 のべき乗でない、のいずれでも例外を投げること（黙って空の結果を返さない） |

### 10.2.1 ブラウザ側スモークテスト（`node tools/smoke.mjs`）

ビルド済みの単一 HTML を**ヘッドレス Chromium で `file://` から開き**、UI を実際に操作して
32 項目を検証する（外部依存なし。Chromium は同梱のものを自動検出する）。
初期計算・231 行の展開・n=20 モードの入力・中心遮蔽・単位切替・表示切替・JSON/CSV 往復・

> **ハーネスの制約（重要）**: ヘッドレスの `--virtual-time-budget` は仮想時計を早送りするため、

> 使い切ってページがダンプされる）。
> このためスモークテストは `?backend=main` で計算経路をメインスレッドに固定して走らせ、
> 性能は `tools/bench.js`（Node）で、Worker 側のコードは UT-20（Node の `vm`）で検証する。
> なお Blob URL からの Worker が `file://` でも起動すること自体は実機で確認済み（§3.3）。

## 12. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 参照実装と規約がずれる（インデックス・正規化・グリッド） | 既存データと数値が合わない | §5.1 の R-1〜R-6 を厳守。UT-04 / UT-18 で全件突き合わせ。**特に `linspace(−1,1,N)` の端点含みグリッド**（§5.4）と **モード列が Noll 2 始まり**（§7.2）に注意 |
| 位相の単位の取り違え（rad と λ） | 収差量が `2π` 倍ずれる | 内部は rad に統一。UI に単位を常時表示。Maréchal 式も rad 版を使う（§5.8） |
| `n = 20` での階乗の精度欠落 | 高次項が静かに壊れる | 係数は `BigInt` で厳密計算（§5.10）。UT-05 |
| 231 モードのメモリ | ブラウザが重くなる / 落ちる | マスク内パック + 遅延生成 + LRU 上限（§4.3）。IT-04 / IT-05 |
| 231 行の UI が重い | 操作がもたつく | グループ化 + 仮想スクロール（§9.2）。IT-08 |
| JS の計算速度が §8.2 に届かない | 操作がもたつく | M0 で先に実測。不足時はカーネルのみ WASM 化 → それでも不足なら H-3。**UI は無変更で移行できる設計**（§4.1） |
| `file://` 固有の制約を踏む | 起動しない / 機能が欠ける | §3.3 の回避策を設計時に織り込む。IT-06 で実機確認 |
| WebGL2 が使えない環境 | 画像が出ない | 起動時に判定して Canvas2D へ自動フォールバック（§3.6）。IT-07 |
| FFT のスケール・シフト規約の取り違え | PSF が微妙にずれ、気付きにくい | UT-09〜UT-11（Airy 半径・チルト移動量）で規約ごと検証 |
| 遮蔽瞳での係数由来 RMS の誤用 | 指標が実態とずれる | RMS は必ずマップから数値計算（§5.6）。UI に注記 |

## 付録 C. 参照実装 (`torchmfbd/zern.py`) の要約と fixture 生成手順

### C.1 規約の根拠

| 規約 | 根拠となる実装 |
| --- | --- |
| R-1 Noll | `deconvolution.py: noll_Z = 2 + np.arange(n_modes)` → `n, m = zern.zernIndex(jz)` |
| R-2 Noll 正規化 | `Z_nm(..., normalize_noll=True, ...)` で呼ばれる。`m=0 → √(n+1)`、`m≠0 → √2·√(n+1)`、`n=m=0 → 1` |
| R-3 方位角 | `m > 0 → cos(\|m\|θ)`、`m < 0 → sin(\|m\|θ)` |
| R-4 グリッド | `x = np.linspace(-1, 1, npix)` / `xx, yy = np.meshgrid(x, x)` / `rho = overfill * sqrt(xx²+yy²)` / `theta = arctan2(yy, xx)` / `aperture_mask = rho <= 1.0` |
| R-5 位相の単位 | `phase = pupil * torch.exp(1j * wavef)` — `2π` を掛けていない → `wavef` は rad |
| R-6 PSF | `ft = fft2(phase)` → `psf = (conj(ft)*ft).real` → `psf / psf.sum()` → `otf = fft2(psf_norm)` |
| `q` = `overfill` | `overfill = util.psf_scale(λ, D, pixel_size) = 206265·λ/(D·pixel_size)` = 1 λ/D あたりの像面画素数 |

### C.2 fixture 生成スクリプト

Python と numpy が使える**開発機で 1 回だけ**実行し、出力 CSV を
`tests/fixtures/` にコミットする。以後、製品側もテスト側も Python を必要としない。

```python
# tools/gen_fixtures.py  （開発機でのみ実行）
import numpy as np
from torchmfbd import zern

N, q = 64, 1.0
x = np.linspace(-1, 1, N)
xx, yy = np.meshgrid(x, x)
rho   = q * np.sqrt(xx**2 + yy**2)
theta = np.arctan2(yy, xx)
mask  = (rho <= 1.0)
Z = zern.ZernikeNaive(mask=[])

# (1) Noll インデックス表 j = 1..231
with open('noll_index.csv', 'w') as f:
    f.write('# j,n,m\n')
    for j in range(1, 232):
        n, m = zern.zernIndex(j)
        f.write(f'{j},{n},{m}\n')

# (2) 代表モードの基底マップ
for j in [1, 4, 8, 11, 22, 100, 231]:
    n, m = zern.zernIndex(j)
    zmap = Z.Z_nm(n, m, rho, theta, True, 'Jacobi') * mask
    np.savetxt(f'zmap_noll{j:03d}.csv', zmap, delimiter=',', fmt='%.17g')

# (3) 合成波面と PSF（N=128, q=4 で別途生成）
coeff = {4: 0.30, 11: 0.60, 8: -0.12}      # Noll j -> 係数 [rad]
W = np.zeros((N, N))
for j, c in coeff.items():
    n, m = zern.zernIndex(j)
    W += c * Z.Z_nm(n, m, rho, theta, True, 'Jacobi')
W *= mask
P   = mask * np.exp(1j * W)
psf = np.abs(np.fft.fft2(P))**2
psf /= psf.sum()
np.savetxt('wavefront.csv', W, delimiter=',', fmt='%.17g')
np.savetxt('psf.csv', np.fft.fftshift(psf), delimiter=',', fmt='%.17g')
```

### C.2.1 本物の torchmfbd との突き合わせ（実施済み）

`tools/gen_fixtures.py` は zern.py の式を純 Python に**転記**したものなので、
numpy が使える環境で本物と一致することを確認する必要がある。
`tools/verify_reference.py` がそれを自動で行う。

```
pip install numpy
git clone --depth 1 https://github.com/aasensio/torchmfbd /path/to/torchmfbd
python3 tools/verify_reference.py --zern /path/to/torchmfbd/src/torchmfbd/zern.py
```

**実施結果（numpy 2.4.6 / Python 3.11.15、10 項目すべて一致）:**

| 検証項目 | 一致度 |
| --- | --- |
| Noll インデックス `zernIndex(j)` の `j = 1…231` | **231 件すべて完全一致** |
| 基底マップ Noll 1 / 4 / 8 / 11 / 22 / 100 / 231 (n=20) | normAbs ≤ 9.5e-15、relSig ≤ 6.1e-13 |
| 合成波面（3 モード、rad） | normAbs 1.1e-14、relSig 1.1e-13 |
| PSF（総和正規化・fftshift 済） | normAbs 9.1e-16、relSig 2.2e-13 |

いずれも倍精度の丸め誤差の範囲であり、転記が正しいことが確認できた。
JavaScript 実装は UT-18 でこの fixture と突き合わせているため、
**本ツールの数値は参照実装まで遡って検証されている**ことになる。

なお `ZernikeNaive.R_nm`（`mode='Standard'`）は Python 3.11 で
`TypeError: 'numpy.float64' object cannot be interpreted as an integer` になることも
このスクリプトで確認済み（C.3 の注意を参照）。

### C.3 生成時の注意

| 注意 | 内容 |
| --- | --- |
| **`mode='Jacobi'` を使うこと** | `mode='Standard'` の `R_nm` は `fact((n+m)/2 - j)` に float を渡すため、**Python 3.10 以降では `TypeError` になる**（`math.factorial` が float を受け付けなくなったため）。torchmfbd 本体も `'Jacobi'` を使っている |
| `zern.py` の import | 先頭で `matplotlib` を import しているため、実行環境に matplotlib が必要 |
| FFT の正規化規約 | 上記スクリプトは総和で正規化するため、`np.fft.fft2` の `norm` 規約は結果に影響しない |
| 出力精度 | `fmt='%.17g'` で倍精度を往復可能な桁数を確保する。UT-18 の許容誤差は相対 1e-10 |
| `fftshift` | 波面は shift せず、PSF のみ `fftshift` して中心を配列中央に置く。本ツールの表示と揃える |
